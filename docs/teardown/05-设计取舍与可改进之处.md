# 05 · 设计取舍与可改进之处

> 前四篇讲“它是什么、怎么做”。本篇评价：作者做了哪些取舍、哪里有局限、可以怎么改。
> 约定：**事实**带文件和行号；**我的判断/建议**会明确标出，不当事实说。
> 本次拆解没有修改原仓库任何文件；下面的“改进”都只是建议。

---

## 一、作者做了哪些取舍

### 取舍 1：把“方法”写成提示词，而不是写成程序

- **做法**：整套流程是一份 Markdown（`SKILL.md`，682 行），脚本只处理字幕和做粗检查。README 说它“基于开放的 Agent Skills 协议”，可在多种 AI 工具里运行（`README.md:22`）。
- **得到**：容易移植（复制一个文件夹就行），读者看得懂（用平实中文写成）。
- **付出**：同一份提示词在不同 AI、不同日期会跑出不同结果，难以重复。仓库里没有给出“同样输入跑两次差多少”的数据（我没有找到，推测：没有做过）。

### 取舍 2：宁少勿多

- **做法**：心智模型 3-7 个，“3个深刻的模型远好于10个浅薄的原则”（`SKILL.md:373`）；上限写进通过标准（`SKILL.md:546`）。
- **得到**：成品聚焦，不像语录堆。
- **付出**：复杂人物的某些侧面会被舍弃；取舍标准“排他性”依赖 AI 的主观判断（见 02 篇 6.6）。

### 取舍 3：保留矛盾，不做“完美人设”

- **做法**：矛盾写成“内在张力”，至少 2 对（`SKILL.md:551`；`extraction-framework.md:73-97`）。
- **得到**：人物更真实，也更能防止“粉丝滤镜”。
- **付出**：对想要“明确答案”的使用者，角色有时会显得自相矛盾（推测）。

### 取舍 4：诚实边界放在显眼位置

- **做法**：每个 skill 必须写“做不到什么”；规则里还有“宁可生成诚实标注局限的 60 分 skill，也不要看起来完美的 90 分 skill”（`SKILL.md:330`）。
- **得到**：可信度。这是女娲最值得学习的设计之一。
- **付出**：成品里要多一段并不增加“功能”的文字；使用者可能直接跳过不读（推测）。

### 取舍 5：人工检查点 vs 不阻塞交付

仓库里有两条看起来互相拉扯的规则：

- 有 4 个 🔴 CHECKPOINT 要求暂停等用户确认（`SKILL.md:334,413,557,578`）；
- 反模式 #10 又说“把确认检查点变成交付阻塞”是错的（`SKILL.md:622`），Phase 0A 也说“能给默认值就给默认值”（`SKILL.md:62`）。

我的理解（推测）：检查点的作用是“展示结果、让用户有机会纠偏”，而不是“没有用户回答就不干活”。两条规则合起来是“先给产出，再请你改”。但文字上没有明说二者如何协调，新手读时可能困惑。

### 取舍 6：核心文件不收外部修改

- **做法**：`SKILL.md` “不接受外部PR改动”，发现问题请开 issue，由维护者实现并致谢（`CONTRIBUTING.md:5-7`）。社区作品走 `COMMUNITY.md` 索引，门槛是评分卡 ≥70 分（`CONTRIBUTING.md:21-27`）。还有一个机器人自动检查收录申请（`.github/scripts/community_check.py`）。
- **得到**：方法论版本统一，质量口径一致。
- **付出**：改进的速度取决于一位维护者；外部贡献者不能直接修正文档里的不一致（如下文的“自创术语/排他性”）。仓库对此的说明是“每一行都经过维护者的实测验证和版本化优化”（`CONTRIBUTING.md:5`）。

### 取舍 7：永久拉黑知乎、公众号、百度百科

- **做法**：任何维度都不用（`SKILL.md:310-314,616`），中文只接受权威媒体、播客和 B 站原始视频。
- **得到**：减少洗稿和失真。
- **付出**：一些中文人物的一手内容可能恰好只出现在被拉黑的平台上（推测）。仓库没有给“经核实的一手原文可例外”的路径。

### 取舍 8：免责声明只说一次

- **做法**：“免责声明仅首次激活时说一次”，重复算违规（`skill-template.md:29`；`SKILL.md:621` 要求保留防漂移规则）。
- **得到**：沉浸感好。
- **付出**：长对话后期，用户可能忘了这是“推断出来的视角”。仓库用“未表态主题标推断”“关键引用可分辨”两条纪律作弥补（`skill-template.md:32-33`），但其中那两条是后来才加入模板的（提交 `27642f5`，2026-07-27）。

### 取舍 9：用 AI 评测 AI

- **做法**：评分卡强调答题与评分分开，不自评自证（`fidelity-scorecard.md:156,158`）。
- **得到**：比“自己说自己好”可靠。
- **付出**：评测者仍是 AI。所有 15 张评分卡里记录的都是 Claude 系列模型（如 `examples/steve-jobs-perspective/FIDELITY.md:3`、`examples/munger-perspective/FIDELITY.md:3`），没有人类专家或第三方的复核记录。每个 skill 只有 3 道立场题 + 1 道边缘题，样本量很小——比如马斯克的“边缘诚实度”12/20 完全由 1 道题决定（`examples/elon-musk-perspective/FIDELITY.md:9,24`）。

## 二、已发现的局限（带证据）

### A. 自带脚本有实现缺陷（我实际运行验证过）

| 脚本 | 问题 | 证据 |
|---|---|---|
| `quality_check.py` | 诚实边界只数 `-`/`*` 开头的行，不数 `1.` `2.` 编号 → 对编号写法的 skill 误判为 0 条 | `quality_check.py:72`；15 个示例里 13 个因此或其他原因未过，全部栽在这一项 |
| `quality_check.py` | “一手来源占比”的正则带 `re.DOTALL`，匹配起点跑偏 → 15 个示例上全部“跳过检查” | `quality_check.py:88`；我用 Python 复现了匹配从第 16 行开始 |
| `quality_check.py` | “局限”检查只要全文出现一次“局限/盲区”就通过，不核对每个模型 | `quality_check.py:47` |
| `merge_research.py` | 来源数 = 网址个数；一手/二手 = 关键词个数；矛盾 = 关键词命中。仅是粗估 | `merge_research.py:182-196,216-224` |
| `merge_research.py` | 只认 `references/research/01~06`；部分示例没有该目录，直接退出 | `merge_research.py:233-237` |
| `download_subtitles.sh` | 用 `find -newer /tmp/.ytdlp_marker`，脚本里无处创建该文件，第一支“中文人工字幕”分支很可能永远判不成功，自动降到下一支（推测，未实际运行 yt-dlp） | `download_subtitles.sh:27` |

### B. 文档自身有不一致

1. **“三重验证”的第三重**：`SKILL.md:361` 写“自创术语”，同一文件 `370-372`、`extraction-framework.md:26`、`README.md:266` 写“排他性”（见 02 篇 6.1）。
2. **“四件事”vs 实际阶段**：README 讲四步（`README.md:262-270`），`SKILL.md` 有 Phase 0 / 0.5 / 1 / 1.5 / 2 / 2.5 / 3 / 4 / 5。
3. **人物数量**：README 同时出现 13 和 14 个人物的说法（`README.md:194,284,376`）。
4. **模板与成品的差距**：模板的角色规则很短（`skill-template.md:22-35`），成品多出 STOP/EXIT/CHECKPOINT 三问、Fallback 树、反例黑名单（如 `examples/munger-perspective/SKILL.md:42-172`）。`SKILL.md` Phase 3 没有说明这些是怎么加上去的（推测：来自 Phase 5 精炼或后续手工优化，提交信息里出现过“全部人物Skill升级Agentic Protocol”`4282c4c`、“sync 14 perspective skill optimizations”`8dff046`）。所以读者仅靠模板**复刻不出**成品的全部形态。
5. **“自包含”原则与示例不一致**：`SKILL.md:179` 说调研文件必须在 skill 目录内；但马斯克、芒格的索引指向仓库外路径，并有“未存文件”（见 03 篇）。README 却写“每个example都包含完整的调研文件”（`README.md:300`）、“all with full research data”（`README.md:376`）。再多一例：MrBeast 的 `research/` 里没有 `01-writings.md`（只有 02~06），而标准是 6 个。

### C. 成品质量的个别瑕疵

- 芒格 `SKILL.md` 第 418-428 行有乱码（替换符 �，见 03 篇）。
- 马斯克 skill 没有“谈及自己公司业务时要披露利益相关”的规则（评分卡扣 8 分，见 03 篇）。
- 5 个示例（马斯克、费曼、芒格、纳瓦尔、塔勒布）没有 `references/research/` 子目录，布局与现行规范不同。

### D. 方法本身的局限

1. **只是公开信息的快照。** 仓库自己承认“公开表达 ≠ 真实想法”“截止到调研时间的快照”（`README.md:182-186`）。
2. **“更新已有 Skill”只增量处理三路**（对话、决策、时间线），不重新验证旧模型（`SKILL.md:584-595`）。
3. **没有与“朴素角色扮演”做对比实验。** README 反复强调“不是角色扮演”（`README.md:96`），但我在 `SKILL.md`、`references/`、`README.md`、`CONTRIBUTING.md` 里搜索“baseline/基线/对照组/普通角色扮演”均无结果（`grep` 验证）。所以“比普通提示词更好”这一核心主张，在仓库内缺少直接证据（只有评分卡的绝对分数）。
4. **A 级通胀的可能**：15 个全部 ≥89（推测：评分标准较宽，或评分者与制作者同属一个体系，二者都可能）。
5. **成本不透明。** 只有“数十美元”“约标准档 1/3”这类定性描述（`SKILL.md:52,56`），没有按模型、按人物给出实测 token 或费用。
6. **示例对话的外推风险。** README 把乔布斯“评价”OpenAI/Anthropic 的对话放在首页（`README.md:73-94`）。乔布斯 2011 年去世，这些都是框架外推。skill 内部有免责声明，但首页展示处没有逐句提醒（推测：是营销取舍）。
7. **高责任话题的边界不够细。** `CONTRIBUTING.md:35` 要求医疗、法律、投资类 skill 有免责声明和“不能替代专业人士”边界，这一条用于**社区收录**；官方示例里如芒格的投资类建议是否逐个符合，我没有逐一核对。

### E. 安全提示（给想用别人 skill 的读者）

Skill 是“会让 AI 去读写文件、运行命令、上网”的指令。`COMMUNITY.md:5` 自己提醒：社区项目“未经本仓库审计…尤其注意skill内的指令和脚本”。另外，女娲 `SKILL.md` 末尾有一节“版本自检（静默）”，会让 AI 每 30 天读写一个日期文件并对比远程版本，“是否更新由用户决定”（`SKILL.md:673-682`）。这段内容是公开写明的，读者应知道它的存在，并自行判断是否接受。

## 四、给学习者的三点总结

1. **最值得学的是“结构”而不是“人物”**：分维度调研 + 先筛选再写 + 把局限写进成品 + 用独立评测收尾，这几个习惯可以迁移到任何“让 AI 做研究并产出规则”的任务。
2. **别把分数当真理**：高分只说明它通过了作者设计的那套测试，不代表“和真人一样”。
3. **读文档要对照文件**：本仓库的 README 与 `SKILL.md`、示例之间有若干小出入。凡是要依赖的说法，请像本系列一样回到源文件核对。
