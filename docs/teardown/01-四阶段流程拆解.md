## 零、开工之前：Phase 0 / 0.5（README 没写的部分）

**输入**：用户的一句话，比如“蒸馏芒格”，或者“我想提升决策质量”。

**做什么**（`SKILL.md:32-65`）：

1. 先判断是“明确人名”还是“模糊需求”。模糊需求走**诊断路径**：最多追问 2 轮，再推荐 2-3 个候选人，每个要写明“核心镜片 / 为什么适合你 / 局限”（`SKILL.md:90-134`）。
2. 明确人名后，要确认 6 件事：是谁、聚焦方向、用途、新建还是更新、有没有本地语料、选哪个**档位**（`SKILL.md:45-52`）。
3. 档位分“快速 / 标准 / 深度”，开跑前必须告诉用户**成本量级**（`SKILL.md:52-58`），并写明完整蒸馏“单次可消耗数十美元（真实用户案例）”。
4. 用户只说“就做XX”时，**不卡住**，直接用默认值（全面画像、思维顾问、无本地语料、标准档）（`SKILL.md:60-62`）。
5. Phase 0.5 立刻建好目录 `.claude/skills/[人名]-perspective/`，里面预留 `references/research/01~06` 六个文件位置（`SKILL.md:153-169`）。

**为什么这样设计**：

- 先报价再开跑，是被真实事故逼出来的。`SKILL.md:318` 明说失败表里前三条“都在真实用户中发生过（GitHub issue实证）”；反模式 #7 也写“不报成本量级直接开跑”（`SKILL.md:619`）。
- “确认不阻塞交付”（`SKILL.md:62`、反模式 #10 `SKILL.md:622`）：能给默认值就给，别让用户先回答一堆问题。（推测：这是对“AI 助手爱反复提问”这一常见毛病的纠正。）
- 调研文件必须落在 skill 目录**内部**，这样“复制整个目录就能独立使用”（`SKILL.md:179`）。这条规则后面会在 `03` 篇里被检验：有些示例并没做到。

## 一、阶段一：六路并行调研（Phase 1 + 1.5）

### 输入

- 人名（及 Phase 0A 里确认的各项）。
- 可选的**本地语料**：书籍 PDF、访谈文字稿、字幕等。有的话比上网搜“质量高得多”（`SKILL.md:51`）。

### 提示词是怎么写的

主 AI 一次派出 **6 个子代理**，每个只管一个维度（`SKILL.md:224-231`）：

| 子代理 | 查什么 | 重点提取 | 输出文件 |
|---|---|---|---|
| 1 著作 | 书、长文、论文 | 反复出现≥3 次的论点、自创术语 | `01-writings.md` |
| 2 对话 | 播客、长访谈 | 被追问时怎么答、改变立场的瞬间 | `02-conversations.md` |
| 3 表达 | 推特、微博等短文 | 高频词、幽默方式 | `03-expression-dna.md` |
| 4 他者 | 批评、传记、书评 | 外部观察到的模式、争议 | `04-external-views.md` |
| 5 决策 | 重大决策、转折点 | 言行一致/不一致 | `05-decisions.md` |
| 6 时间线 | 生平里程碑 | 思想转折、**最近 12 个月** | `06-timeline.md` |

给子代理的任务书有固定结构（`SKILL.md:243-260`）：**你的任务 → 搜索方向 → 输出要求（写入哪个文件、标来源和可信度、区分一手/二手、矛盾直接记录） → 信息源黑名单**。

所有子代理共享四条硬要求（`SKILL.md:233-237`）：

1. 结果必须写进文件（“不存文件的调研等于没做”，`SKILL.md:178`）。
2. 标明来源和可信度，“一手 > 二手 > 推测”。
3. 区分“他说过的 / 别人说他的 / 我推断的”。
4. 发现矛盾就保留，“不要和稀泥”。

另外有一张**信息源优先级表**（`SKILL.md:298-306`）和**永久黑名单**：知乎、微信公众号、百度百科（`SKILL.md:310-312`），理由是“洗稿严重、无法验证”。

### 输出

`references/research/` 下 6 份 Markdown。以乔布斯示例为例，这 6 份共 2497 行（`examples/steve-jobs-perspective/SKILL.md:385`；各文件行数可用 `wc -l` 复核）；每条信息用 `[一手]` `[二手]` `[推断]` 打标签（`examples/steve-jobs-perspective/references/research/01-writings.md:3-4`）。

### Phase 1.5：调研检查点

所有子代理完成后，**暂停**，给用户看一张摘要表：每个维度的来源数、关键发现、矛盾点、信息不足的维度（`SKILL.md:334-350`）。用户说 OK 才继续。可以用 `scripts/merge_research.py` 自动生成这张表（`SKILL.md:275-277`）。

### 为什么这样设计

- **分 6 路而不是让一个 AI 查到底**：每路有独立焦点，又各写各的文件。这样做的好处，仓库在失败表里间接承认了——上下文窗口不够时，“调研文件本身就是断点”，新会话可从文件恢复（`SKILL.md:323`）。
- **专门留一路查“别人怎么批评他”**：反模式 #3 写“负面占比不足=调研不合格”（`SKILL.md:615`），用来对抗“粉丝滤镜”。
- **偏爱长文、争议、立场变化**（“品味守则”，`SKILL.md:603-607`）：长文比金句更能暴露思维结构；改变立场的地方比一贯坚持的更有信息量。
- **有降级方案**：运行环境不支持并行就改串行；上下文不够就分三段会话；搜索工具坏了就转本地语料（`SKILL.md:316-330`）。关键规则：“宁可生成一个诚实标注了局限的60分Skill，也不要生成一个看起来完美但实际上在编造的90分Skill。”（`SKILL.md:330`）

### 这一步的局限（推测）

- `scripts/merge_research.py` 数“来源数”的方法是数 **URL 的个数**，数“一手/二手”的方法是数**关键词出现次数**（`scripts/merge_research.py:182-196`）。所以它是粗略估算，不是真的核对来源。比如“总结”“分析”这些常见词会被算作二手标记（`merge_research.py:189`）。我用乔布斯示例实际运行过：“决策”一路显示来源数 0（该文件把来源写成文字名称而非网址），“著作”一路被报出一处“矛盾点”，内容只是“争议。不妥协”，是关键词误报。另外它只认 `references/research/01-…06-….md` 这组文件名；对马斯克示例运行会直接报“目录不存在”并退出（`merge_research.py:233-237`）。
- `scripts/download_subtitles.sh:27` 用 `find ... -newer /tmp/.ytdlp_marker`，但脚本里没有任何一行创建这个文件。按 `find` 的行为，这一支会找不到文件，随后降级到下一支（推测，未实际运行过 yt-dlp）。

## 二、阶段二：三重验证提炼（Phase 2 + 2.5）

**这一阶段的详细解析在 [02-三重验证机制](02-三重验证机制.md)。** 这里只讲它在流程中的位置。

### 输入

`01~05` 号调研文件（`SKILL.md:366-367`）。

### 做什么（`SKILL.md:363-409`）

| 步骤 | 内容 | 产出规模 |
|---|---|---|
| 2.1 心智模型 | 先列出 15-30 个候选论点，用三重验证筛，取前 3-7 个 | 3-7 个 |
| 2.2 决策启发式 | “如果 X 则 Y”的快速规则，要有案例 | 5-10 条 |
| 2.3 表达 DNA | 句式、词汇、节奏、幽默、确定性、引用习惯 | 6 个维度 |
| 2.4 价值观与反模式 | 3-5 条价值排序 + 明确反对的东西 + **内在矛盾** | — |
| 2.5 智识谱系 | 他受谁影响、影响了谁 | — |
| 2.6 诚实边界 | 做不到什么（4 条必写） | — |

### Phase 2.5：提炼检查点

再次暂停，把“模型 N 个、启发式 N 条、DNA 的 3 个特征、张力 N 对、边界 N 条”摆给用户确认（`SKILL.md:413-427`）。**理由写得很直白**：提炼是“主观判断最重的环节”，确认后再构建，“避免写完400行SKILL.md才发现方向不对”（`SKILL.md:427`）。

### 为什么这样设计

- “宁少勿多——3个深刻的模型远好于10个浅薄的原则”（`SKILL.md:373`）。
- 把矛盾当特征保留：`references/extraction-framework.md:73-97` 把矛盾分成时间性、领域性、本质性三类，并列出三种错误做法（选一边、编调和解释、假装没有）。

## 三、阶段三：构建 Skill（Phase 3）

### 输入

阶段二的提炼结果 + `references/skill-template.md`（模板）+ `references/extraction-framework.md`（自检清单）。

### 提示词怎么写

不是自由发挥，而是**“填空”**：模板规定了章节顺序，`SKILL.md:439-455` 用一张表说明每一章的内容从哪个调研文件来。例如：

| 模板章节 | 来源 |
|---|---|
| 身份卡 | 时间线 + 著作 → 用此人语气写 50 字自我介绍 |
| 心智模型 | Phase 2.1 结果，每个含名称/证据/应用/局限 |
| 诚实边界 | Phase 2.6 结果 + 调研时间 |

模板里最关键的是 **“角色扮演规则”**（`references/skill-template.md:22-35`）：

- 用“我”不用“他会认为”；
- 免责声明**只说一次**；
- 不确定时按此人的方式犹豫，而不是跳出角色；
- 未表态的话题要先说明“这是框架推断，非本人立场”（`skill-template.md:32`）；
- 引用招牌句要附极简出处，让“本人原话”和“框架推断”可分辨（`skill-template.md:33`）；
- 用户说“退出”才恢复正常。

此外 Phase 3 有一个特别要求：**“回答工作流（Agentic Protocol）”**（`SKILL.md:457-513`）。道理是：没有它，人物 skill 遇到需要事实的问题会“凭训练语料编造”；有了它，会像真人一样“先做功课再发言”（`SKILL.md:459`）。工作流分 3 步：

1. 分类：事实型 / 纯框架型 / 混合型；
2. 查资料：**必须**用搜索工具；查什么由心智模型**反推**——比如芒格相信“逆向思考、激励机制”，所以研究“公司”时要查“护城河、管理层激励、最大风险”（`SKILL.md:503-508`）；
3. 用人物口吻作答，用户看到的是判断，不是调研报告。

### 输出

`.claude/skills/[人名]-perspective/SKILL.md`（`SKILL.md:518-519`）。成品体量约 2.5 万到 3.2 万字节（`wc -c examples/*/SKILL.md`，主题 skill `x-mastery-mentor` 约 1.7 万）。

### 为什么这样设计

- **防止“说得像但乱说”**：Agentic Protocol 把“先研究再回答”写成硬流程。
- **防止“演着演着变回通用助手”**：反模式 #9 要求“防漂移机制”必须完整保留（`SKILL.md:621`）。
- **description 控制在约 300 字、不超 1024 字**：长尾关键词会“超限报错、每session烧token、抬高误触发率”（`SKILL.md:443`）。这是对一次真实 bug 的修复（`CONTRIBUTING.md:7` 提到 PR #59 发现 description 超限）。

### 与示例的差距（重要，细节见 03 篇）

示例 skill 里还有模板**没有**的东西：`🛑 STOP`、`🚪 EXIT TRIGGER`、`🔴 CHECKPOINT` 三问、“失败模式与 Fallback 树”、“反例黑名单”（如 `examples/munger-perspective/SKILL.md:42-46,122-172`）。模板里只有简单的角色规则。可见**模板没有完全反映成品的形态**（推测：成品经过 Phase 5 精炼或后续手工优化，见 `examples/*/` 的 git 历史 “sync 14 perspective skill optimizations”）。

## 四、阶段四：质量验证（Phase 4）

### 输入

刚生成的 SKILL.md。

### 做什么（`SKILL.md:525-557`）

由**子代理**（独立于主 Agent，“避免自评偏差”）做三项测试：

| 测试 | 怎么做 | 期望 |
|---|---|---|
| 已知测试 | 选 3 个此人公开表态过的问题，让带着新 skill 的子代理回答，对比真实立场 | 方向一致 |
| 边缘测试 | 选 1 个此人没讨论过的问题 | 说“基于模型 X 和 Y 的推断，可能…但不确定”，**不应斩钉截铁** |
| 风格测试 | 写一段 100 字分析 | 有此人特征；不是通用 AI 鸡汤；不是原话拼凑 |

然后对照 6 项**通过标准**（`SKILL.md:545-552`）：

| 检查项 | 通过 | 不通过信号 |
|---|---|---|
| 心智模型数量 | 3-7 个，各有来源 | <3 或 >10 |
| 每个模型的局限 | 写明失效条件 | 只写优点 |
| 表达DNA辨识度 | 读 100 字能认出是谁 | 像通用 ChatGPT |
| 诚实边界 | ≥3 条具体局限 | 只有“不能替代本人” |
| 内在张力 | ≥2 对矛盾 | 观点高度一致（太假） |
| 一手来源占比 | >50% | 主要靠二手 |

不通过就回 Phase 2，**最多循环 2 次**，之后在诚实边界里标明薄弱处，“交付当前最优版本而非无限打磨”（`SKILL.md:554-555`）。

### 自动化的那一半

`scripts/quality_check.py` 把这 6 项里**能用文字规则判断的**变成了脚本（`quality_check.py:116-123`）。它的检查方式（均为正则表达式，即“按文字模式查找”）：

- 数量：数形如“### 模型N”的标题（`quality_check.py:21`）；
- 局限：只要全文出现“局限/失效/盲区”等词就算通过（`quality_check.py:47`）——**不检查每个模型是否都有**；
- 内在张力：数“张力/矛盾/既…又”等词出现≥2 次（`quality_check.py:80-81`）；
- 一手占比：数“一手/二手”等词，找不到来源章节则**直接判通过**（`quality_check.py:90-91`）。

所以这个脚本能抓到“明显缺章节”，抓不到“写了章节但内容空洞”。风格辨识度、立场是否一致，脚本完全没有碰（推测：这些只能靠 AI 测试）。

**实测（我对 15 个官方示例逐个运行了这个脚本）**：

- 只有 2 个（乔布斯、张雪峰）得到 6/6，其余 13 个至少有一项不通过，而且这 13 个无一例外都在“诚实边界”一项上不通过（显示 0 条，只有特朗普显示 1 条）。原因是脚本只数以 `-` 或 `*` 开头的行（`quality_check.py:72`），而多数示例把边界写成 `1.` `2.` 的编号列表，被漏数。乔布斯显示“3 条”并通过，其实是数到了边界章节末尾的 3 行短横线条目（调研时间等），它真正的 5 条编号边界没被数到。
- “一手来源占比”在全部 15 个示例上都显示“未标记来源类型（跳过检查）”。原因：该正则带 `re.DOTALL`，`.*` 能跨行，匹配起点落在文件开头第一个二级标题，而不是“调研来源”章节（我用 Python 复现了匹配起点，是第 16 行的“角色扮演规则”）。也就是说，Phase 4 里“一手占比 >50%”这条标准，在脚本层面实际没有生效。
- `x-mastery-mentor` 是主题 skill，结构不同于人物 skill，只得 1/6（`SKILL.md:636-645` 说明主题 skill 要用变体模板）。

以上两个脚本问题都不属于“设计思路错误”，是实现缺陷；本次拆解不修改原仓库，处理建议见 [05 篇](05-设计取舍与可改进之处.md)。

### Phase 4 之后：保真度评分卡

仓库另有一套对外的评分方法（`references/fidelity-scorecard.md`），满分 100，分 5 维：立场一致性 30、风格辨识度 20、边缘诚实度 20、来源透明度 15、结构完整度 15（`fidelity-scorecard.md:160-166`）。关键铁律：**答题 agent 和评分 agent 必须是两个**，依据是一篇被引用的论文称 LLM 自评准确率仅 46.4%（`fidelity-scorecard.md:156`；论文本身我没有核查，仅转述仓库的说法）。

### 为什么这样设计

- **用“已知答案”的题检查**：别人公开说过什么是可查证的，所以能当“标准答案”。
- **专门测“没说过的”**：这是区分“理解框架”和“背诵语录”的办法。
- **限定次数**：避免无限打磨，也控制成本（`SKILL.md:555`）。

## 五、收尾：Phase 5 双 Agent 精炼

Phase 4 通过后**自动**并行启动两个子代理（`SKILL.md:563-580`）：

- Agent A：对 SKILL.md 做 8 维度结构评估，干跑 3 个测试 prompt，给出“最弱 2 个维度”的改进（要附改后文本）。
- Agent B：评审触发条件是否覆盖真实场景、角色规则是否可操作，给出 2-3 处文本改动。

主 Agent 综合后展示变更，请用户确认。目标：让 skill “激活即执行”，“知道先做什么、碰到什么停下来”（`SKILL.md:580`）。

README 说这套评估来自作者的另一个项目“达尔文.skill”（`README.md:250-252`），本仓库内没有它的代码。

## 一图总结：每个阶段的“输入 → 提示词 → 输出 → 为什么”

| 阶段 | 输入 | 提示词的形态 | 输出 | 核心“为什么” |
|---|---|---|---|---|
