# 02 · 三重验证机制

> 这是女娲最核心的一道“过滤器”：从一大堆“这个人说过的话”里，挑出哪些配被称为他的**心智模型**。
> 依据主要是 `references/extraction-framework.md:5-34` 和 `SKILL.md:363-374`。

## 1. 它要解决什么问题

假设你查完资料，手上有一个人的几十万字材料。里面有：

- 他反复讲的核心想法；
- 他某次采访里随口一说的观点；
- 所有聪明人都会说的大道理（“要坚持”“要学习”）；
- 网上流传但他其实没说过的“名言”。

如果全塞进 skill，结果只会是一份“鸡汤合集”。所以需要一个标准，回答：**哪些只是话，哪些是他看世界的“镜片”？**

“心智模型（mental model）”在这里的意思：一个人反复用来理解各种问题的思考套路。比如芒格的“逆向思考”：遇到任何问题，先想“怎么会失败”。

## 2. 三道关卡

依据 `references/extraction-framework.md:7-33`：

| 关卡 | 问的问题 | 仓库给的例子 |
|---|---|---|
| ① 跨域复现 | 这个想法是不是在**至少 2 个不同领域**里都出现过？ | 纳瓦尔的“杠杆”出现在财富、个人成长、职业选择三处（`extraction-framework.md:12-16`） |
| ② 有生成力 | 拿它能不能**推断**他对一个新问题的立场？ | 芒格的“逆向思维”：问“如何成功”→他会先想“如何确保失败”（`extraction-framework.md:21-24`） |
| ③ 有排他性 | 是不是**不是所有聪明人**都这么想？ | “反脆弱”是塔勒布的，不是人人都这样看（`extraction-framework.md:29-30`） |

筛选结果（`extraction-framework.md:32-33`，`SKILL.md:372`）：

- 三关都过 → **心智模型**；
- 只过 1 到 2 关 → 降级为**决策启发式**（“如果 X 则 Y”的规则）；
- 一关都没过 → 丢弃。

之后还有两道“收口”动作（`SKILL.md:373`）：按排他性强弱排序，只留前 3-7 个，“宁少勿多”。

### 一个演示（我自己编的例子，不是仓库里的）

假设在调研一位创业者时，得到两个候选：

| 候选论点 | 跨域？ | 生成力？ | 排他性？ | 结论 |
|---|---|---|---|---|
| “先做减法，砍掉九成” | 产品、公司战略、个人时间都用到 | 能：面对新项目会先问“该砍什么” | 不是人人这么想 | 三关全过 → 心智模型 |
| “要努力，别放弃” | 到处都有 | 推不出任何具体立场 | 谁都会说 | 0 关 → 丢弃 |
| “某次发布会前一定要穿黑色上衣” | 只在一个场合 | 推不出别的 | 有个性 | 只过 1 关 → 最多算一条习惯，不是模型 |

## 3. 在流程里它具体怎么执行

`SKILL.md:365-374` 的操作步骤：

1. **扫描**：读 `01~05` 号调研文件，列出所有候选论点，“通常会得到15-30个”。
2. **逐个过三关**。
3. **排序取舍**，留 3-7 个。
4. **记录格式**：名称、一句话、证据（≥2 个场景）、应用方式、局限性。

随后还有 **Phase 2.5 检查点**让用户确认（`SKILL.md:413-427`），以及 **Phase 4** 里的“每个模型有来源证据”“每个模型写明局限”等通过标准（`SKILL.md:545-552`）。

## 4. 与“普通角色扮演提示词”的对比

先说明：下面“普通角色扮演提示词”指网上常见的那类一句话指令，比如“你现在是芒格，请用芒格的口吻回答”。这是我对一类常见做法的概括，**不是仓库里的内容**（推测性的参照物）。右列全部来自仓库。

| 维度 | 普通角色扮演提示词 | 女娲生成的 skill |
|---|---|---|
| 知识来源 | 完全依赖 AI 训练时“记住”的印象，可能混入伪造名言 | 先分 6 个维度实地调研，落成文件，并区分一手/二手/推断（`SKILL.md:233-237`）；引语必须有出处，否则宁可不用（反模式 #1，`SKILL.md:613`） |
| 写什么进去 | 没有筛选标准，想到什么写什么 | 三重验证；通不过排他性的“通用道理”不进心智模型（反模式 #2，`SKILL.md:614`） |
| 数量 | 常常罗列很多条 | 3-7 个模型，上限明确（`SKILL.md:373`） |
| 矛盾 | 倾向塑造“完美形象” | 保留矛盾，写成“内在张力”，通过标准要求≥2 对（`SKILL.md:551`，`extraction-framework.md:73-97`） |
| 负面信息 | 通常没有 | 专设一路调研查批评；“负面占比不足=调研不合格”（`SKILL.md:615`） |
| 每条结论的失效条件 | 通常没有 | 每个模型必须写“局限”（`skill-template.md:49`） |
| 遇到事实问题 | 凭印象答，易编造 | Agentic Protocol：先分类，必要时强制用搜索工具查（`SKILL.md:457-513`） |
| 没表态过的话题 | 往往编一个看似合理的立场 | 要求先声明“这是框架推断，非本人立场”（`skill-template.md:32`）；若此人本来就沉默，就“忠实呈现那个沉默” |
| 防止演着演着“变回通用AI” | 无 | 免责声明只说一次、退出触发词、防漂移规则（`SKILL.md:621`；`examples/munger-perspective/SKILL.md:42-53`） |
| 怎么知道好不好 | 靠人感觉 | 三项独立子代理测试 + 6 项通过标准 + 可选 100 分评分卡（`SKILL.md:525-557`，`fidelity-scorecard.md`） |

**一句话概括差别**：普通角色扮演是“让 AI 模仿这个人的样子”；女娲是“先把这个人的思维拆成可检查的零件（模型、启发式、边界），再让 AI 按零件运行”。README 也用类似的话区分：“不是在复读名人语录，是在用名人的认知框架帮你分析”（`README.md:96`）。

## 5. 机制的强项

1. **有明确的取舍标准**。“排他性”尤其好：它直接针对 AI 最容易犯的错——把正确的废话当成独特见解。
2. **降级而不是丢弃**。只过一两关的想法变成“决策启发式”，既保留了信息，又不抬高地位。
3. **与“反模式黑名单”和“诚实边界”配合**：筛选（进什么）+ 禁止（不做什么）+ 声明（做不到什么）三层都有。

## 6. 机制的弱点与不一致（本篇最重要的批判部分）

### 6.1 “三重验证”的第三重，仓库内有两种说法

- `SKILL.md:361`（Phase 2 开头）写的是“跨域复现、生成力、**自创术语**”。
- 但 `SKILL.md:370-372`、`references/extraction-framework.md:26-30`、`README.md:266` 写的第三重是“**排他性**”。

“自创术语”（如芒格的 Lollapalooza）和“排他性”不是同一件事。哪一个是作者的本意，仓库没有说明。（推测：早期版本用“自创术语”，后来改成“排他性”，`SKILL.md:361` 这句话没同步更新。我没有逐个提交核对，所以这只是推测。）

### 6.2 “过 2 重”怎么处理，两处措辞不同

- `extraction-framework.md:32-33`：只过 **1** 重 → 降级；**0** 重 → 不纳入。没有提到恰好过 2 重。
- `SKILL.md:372`：三重通过 → 模型；**仅 1-2 重** → 降级；0 重 → 丢弃。

后者把 2 重也归入降级，更明确。以 `SKILL.md` 为准，是更稳妥的读法（推测）。

### 6.3 判官和选手是同一个 AI（推测，但有依据）

Phase 2 的文字里，没有任何地方要求“由另一个 agent 来做验证”（`SKILL.md:359-409`）；对比 Phase 4 则明确要求子代理独立测试，“避免自评偏差”（`SKILL.md:525`）。评分卡甚至引用研究称 LLM 自评接近随机（`fidelity-scorecard.md:156`）。按仓库自己的逻辑，让提炼它的同一个 AI 来判断“这个模型是否跨域”，存在同样的偏差风险。

### 6.4 验证结果没有留在成品里

模板里每个模型只有“一句话 / 证据 / 应用 / 局限”四项（`skill-template.md:45-49`），没有“通过了哪几重”这一项。读者拿到成品，无法审计某个模型是怎么被选中的。

再看一个实例：芒格的“逆向思考”在 `examples/munger-perspective/SKILL.md:231-234` 的“应用方式”里列了投资、人生、产品三个领域。但这是“怎么用”的指引，不一定是**芒格本人**在这三个领域用过的证据（芒格的证据部分是 1986 年哈佛演讲等，`SKILL.md:226-229`）。所以“跨域复现”在成品文本里是否真被满足，读者看不出来（推测）。

### 6.5 脚本只能数词，不能验证

`scripts/quality_check.py` 检查“局限”和“张力”时，只是在全文里找关键词（`quality_check.py:47,80`）。它不判断模型是否跨域、是否有排他性。所以三重验证本身**没有任何自动化检查**，完全靠 AI 执行时的自觉（推测，基于对脚本的通读）。

### 6.6 “排他性”靠 AI 的“常识”判断

“是不是所有聪明人都这样想”没有可操作的判据，AI 只能靠自己对“聪明人通常怎么想”的印象。这个印象本身来自训练语料，因此可能把热门人物的流行说法误当作独特见解（推测）。

## 7. 小结

三重验证是一个**设计得很清楚、但执行全靠自觉**的筛子：

- 好处：有标准、有数量上限、有降级路径，比“你是X，请扮演”可靠得多。
- 不足：三重内容在仓库里有不一致；没有独立复核；成品里不留痕迹；自动化脚本无法检验。

怎么改进，见 [05-设计取舍与可改进之处](05-设计取舍与可改进之处.md)。
