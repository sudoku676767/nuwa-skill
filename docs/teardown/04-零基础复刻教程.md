# 04 · 零基础复刻教程：自己做一个人物 skill

> 目标：不用写代码，照着做，做出一个“某人的思维视角 skill”，并且会检查它做得对不对。
> 流程依据 `SKILL.md`、`references/` 和 `scripts/`；凡是**我自己加的做法**，会标“（我的建议）”。
> 提示词我用自己的话改写过，并非照搬仓库原文。

## 开始前：你需要知道的三件事

1. **这不是点一下按钮就完事的工具。** 完整流程要让 AI 查大量资料、反复读写文件。仓库自己提醒：完整蒸馏“单次可消耗数十美元（真实用户案例）”（`SKILL.md:52`）。第一次练习请用**快速档**：只查 3 个维度，每个维度最多 5 个来源（`SKILL.md:56`）。
2. **两条路线，任选其一：**
   - **路线 A（推荐）**：你用的 AI 助手支持 Skills（如 Claude Code、Codex、Cursor 等，列表见 `README.md:22`）。安装女娲后对它说“蒸馏××”，它会照 `SKILL.md` 自动走流程（`README.md:104-162`）。你要做的主要是在三个检查点给反馈。
   - **路线 B（手动版，本教程重点）**：任何能聊天、能联网搜索的 AI 都行。你自己当“项目经理”，一步步把提示词交给它，并检查它交回来的文件。这样你能真正看懂每一步。
3. **选人要有底线。** 蒸馏“在世的非公众人物”（同事、前任、普通人）必须有本人同意，仓库把它列为伦理红线（`CONTRIBUTING.md:31-35`，反模式 #8：`SKILL.md:620`）。**第一次练习，请选一位已故、公开资料很多的人物。**

下文用“某人”指代你选的人物。

---

## 第 0 步：准备文件夹

**做什么**：建一个存放成果的目录，结构照 `SKILL.md:153-169`。

**复制这段命令**（在终端运行；把 `某人` 换成英文或拼音，如 `darwin`）：

```bash
git clone https://github.com/alchaincyf/nuwa-skill     # 把仓库拿下来，里面有模板和检查脚本
mkdir -p my-skills/某人-perspective/references/research
cd my-skills/某人-perspective
```

> 如果 `git clone` 的地址换成了你 fork 的仓库，请用你自己的地址。

**怎么检查对不对**：运行 `ls references`，应看到 `research` 这个文件夹。

---

## 第 1 步：六路调研（快速档先做前三路）

**做什么**：让 AI 分别研究某人的不同侧面，**每一路写成一个文件**。文件名必须照下表，因为后面的检查脚本会按这些名字去找（`scripts/merge_research.py:172-179`）。

| 文件名（放进 `references/research/`） | 研究什么 | 快速档 |
|---|---|---|
| `01-writings.md` | 著作、长文 | ✅ |
| `02-conversations.md` | 长访谈、播客 | ✅ |
| `03-expression-dna.md` | 短文/社交媒体里的说话方式 | ✅ |
| `04-external-views.md` | 别人的评价与批评 | 标准档 |
| `05-decisions.md` | 重大决策与结果 | 标准档 |
| `06-timeline.md` | 生平时间线、最近 12 个月动态 | 标准档 |

**复制这段提示词给 AI**（每一路各发一次，只改“研究什么”和“文件名”）：

```
你的任务：调研【某人】的【著作和长文】。
搜索方向：他写的书/长文/论文；反复出现至少3次的核心论点；他自创的术语。
输出要求：
1. 把结果写成 Markdown，保存为 references/research/01-writings.md。
2. 每条信息都标注：来源链接 + 标签 [一手]（他本人原话）/[二手]（别人转述或分析）/[推断]（你归纳的）。
3. 发现互相矛盾的说法，直接并列记录，不要自己调和。
4. 不要使用知乎、微信公众号、百度百科作为来源。
5. 查不到的地方写“信息不足”，不要编造；查不到出处的“名言”不要写进来。
快速版限制：这一路最多使用 5 个来源。
```

（这段是我依据 `SKILL.md:243-260` 的任务书结构改写的：任务 → 搜索方向 → 输出要求 → 黑名单。）

**不用 AI 帮你联网时**：把你手头已有的书、字幕、文章直接发给它，让它按同样格式整理。仓库认为用户自己提供的一手素材“质量比网上搜的高得多”（`SKILL.md:51,214`）。

**怎么检查对不对**（三步，都能做）：

1. 三个文件都存在，且不是空的：`ls -l references/research`。
2. 随便点开一个，**每条信息后面都有链接和 [一手]/[二手]/[推断] 标签**。没有就让 AI 重做。
3. 抽查 2 个链接，点开看内容是否真的对得上。

标准档额外做第 4-6 路时，**第 4 路（批评）不要省**：仓库说“负面占比不足=调研不合格”（`SKILL.md:615`）。

### 检查点 1：运行摘要脚本（标准档，6 个文件齐了再运行）

```bash
python3 ../../nuwa-skill/scripts/merge_research.py .
```

（路径按你实际位置调整：最后一个参数是“skill 目录”，即包含 `references/research` 的那一层。）

你会看到一张表，列出每一路的“来源数量”。**怎么读这张表**：

- 它数的是文件里出现了多少个**网址**，并不核对真假（`merge_research.py:182-186`）。我用乔布斯示例实测过：“决策”一路显示 0 个来源，因为那份文件把来源写成了文字名称而不是网址。所以**数字小不一定代表内容差**，但数字为 0 请自己打开文件看。
- 底部“总来源数<10”会提示“降低期望”（`merge_research.py:295-296`）。
- “矛盾点”是靠关键词（如“矛盾”“争议”）猜的，只能当线索，不是结论。

## 第 2 步：提炼（三重验证）

**做什么**：从调研里挑出 3-7 个“心智模型”。三道关卡见 [02 篇](02-三重验证机制.md)。

**复制这段提示词**（把 01~03 号文件内容或文件夹给 AI）：

```
请阅读 references/research/ 下的所有文件，完成以下任务：
1. 列出所有候选论点（通常 15-30 个），每个写一句话。
2. 对每个候选做三重验证，用表格呈现，每格写“是/否 + 一句理由 + 出处文件”：
   ① 跨域复现：是否在至少 2 个不同领域/话题中出现？
   ② 有生成力：能否据此推断他对一个新问题的立场？给一个推断例子。
   ③ 有排他性：是不是并非所有聪明人都会这样想？
3. 三项都“是” → 标为【心智模型】；只有 1-2 项“是” → 标为【决策启发式】；全“否” → 标为【丢弃】。
4. 最终只保留排他性最强的 3-7 个心智模型。宁少勿多。
5. 另外列出：5-10 条决策启发式（“如果X则Y”，附真实案例）；至少 2 对此人的内在矛盾；至少 3 条这个 skill 做不到的事。
禁止：编造他没说过的话；没有出处的内容不要写。
```

（依据 `SKILL.md:363-409` 和 `extraction-framework.md:5-34`。）

**怎么检查对不对**：

| 检查项 | 通过的样子 |
|---|---|
| 心智模型数量 | 3 到 7 个（`SKILL.md:373`、`SKILL.md:546`） |
| 每个模型的证据 | 至少来自 2 个不同场景，且能在 `research/` 里找到原句 |
| 有没有“万金油” | 如果某个模型换成任何一位成功人士也成立（如“要坚持学习”），让 AI 删掉 |
| 矛盾 | ≥2 对，没有被“调和”掉（`SKILL.md:551`） |

> **（我的建议）** 因为仓库没有让“另一个 AI”复核这一步（见 02 篇 6.3），你可以把这张表交给**另一个聊天窗口**再审一遍：“请挑出三重验证里最牵强的两项。”

### 检查点 2

把“模型名称列表 + 启发式数量 + 矛盾 + 边界”读一遍，问自己：**如果删掉名字，我能认出这是谁的想法吗？**（这条来自 `extraction-framework.md:151`。）不能，就回到第 2 步。

## 第 3 步：构建 SKILL.md

**做什么**：把提炼结果填进仓库的模板。

**复制这段命令**，把模板拿过来当起点：

```bash
cp ../../nuwa-skill/references/skill-template.md ./SKILL.md
```

打开 `SKILL.md`，你会看到整个 \`\`\`markdown 代码块外面有一段说明、里面是真正的模板（`skill-template.md:1-117`）。**请删掉外面的说明文字和代码块的围栏**，只留下里面从 `---` 开始的内容。

**复制这段提示词给 AI**，附上 `SKILL.md`（模板）和第 2 步结果：

```
请把下面的提炼结果填进这份模板，写成一份完整的 SKILL.md：
- 保留“角色扮演规则”整节不要改（它包含防止角色漂移的规则）。
- frontmatter 的 description 控制在 300 字以内，必须包含人名和“用某人的视角”这类触发语，最后加一句“不在一般性问题上自动触发”。
- 每个心智模型都按“一句话/证据/应用/局限”四项填写，局限要写具体的失效条件，不要写空话。
- 在“回答工作流”一节写 3 步：①先判断是事实型/框架型/混合型问题 ②事实型必须先联网查证 ③再用此人的口吻回答。
  第②步里的研究维度，请根据上面的心智模型自行推导（例如这个人看重“激励”，就要查“谁从中获利”）。
- “诚实边界”至少 3 条具体局限，并写明调研日期。
- 用“- ”开头的短横线列表写诚实边界（见下面第 4 步的说明）。
- 所有引语必须来自 references/research/，查不到出处的不要用。
```

（这里的三步工作流来自 `SKILL.md:457-513`；300 字、1024 字上限来自 `SKILL.md:443`。）

**怎么检查对不对**：

1. 没有遗留占位符：`grep -n "\[" SKILL.md`，凡是没替换的“[人名]”“[N]”都要处理（正常的网址链接可忽略）。
2. 打开文件，章节齐全：身份卡、核心心智模型、决策启发式、表达DNA、时间线、价值观与反模式、智识谱系、诚实边界、调研来源（`skill-template.md:37-110`）。
3. 开头 `---` 之间的 `description` 不超过 1024 字（上限，见 `SKILL.md:443`）。

## 第 4 步：自检

### 4.1 用脚本

```bash
python3 ../../nuwa-skill/scripts/quality_check.py ./SKILL.md
```

它检查 6 项（`quality_check.py:116-123`）：心智模型数量、局限、表达DNA、诚实边界≥3、内在张力≥2、一手占比。全部 ✅ 才算“可以交付”（`quality_check.py:141-146`）。

**有两个我实测发现的坑，请先知道**：

1. **诚实边界会被误判为 0 条。** 脚本只数以 `-` 或 `*` 开头的行（`quality_check.py:72`），不数 `1.` `2.` 这样的编号。我对 15 个官方示例逐个运行，13 个没有拿到 6/6，这 13 个全都栽在这一项，哪怕它们的边界写得很完整（例如马斯克示例有 6 条编号边界）。**所以请把你的诚实边界写成“- ”开头的列表**，这是为了让脚本能识别（我的建议）。
2. **“一手来源占比”基本不会真正检查。** 同样 15 个示例，这一项全部显示“未标记来源类型（跳过检查）”。原因是脚本里的正则表达式带了 `re.DOTALL`，`.*` 会跨行，匹配的起点跑到了文件开头的第一个二级标题，没落在“调研来源”那一节（我复现了匹配位置）。所以**这一项要靠你自己数**：在“调研来源”里，一手来源是否多于一半？

### 4.2 用人（对照清单）

打开 `references/extraction-framework.md:124-151` 的“质量自检清单”，逐项打勾。重点四项：

- 每个模型都写了**失效条件**吗？
- 表达DNA读起来像这个人，而不是“通用AI腔”吗？
- 诚实边界写了做不到什么、信息截止日期吗？
- “删掉名字后还能认出是谁”吗？

## 第 5 步：测试（最关键，不要跳）

**做什么**：新开一个**干净的聊天窗口**，只把你写好的 `SKILL.md` 内容发给 AI，让它按这份 skill 回答。依据 `SKILL.md:525-541`。

准备 5 道题：

| 题型 | 数量 | 怎么出 | 通过的样子 |
|---|---|---|---|
| 已知立场题 | 3 | 选此人**公开反复表态**的话题，你能查到他的真实立场 | 方向和关键细节一致 |
| 边缘题 | 1 | 选他**没公开讨论过**但相关的问题（例如他去世后才出现的事物） | 开头说明“这是框架推断，不是本人观点”，并保留不确定性，不斩钉截铁 |
| 风格题 | 1 | 让它写 100 字点评 | 有此人特征；不是鸡汤；不是名言拼凑 |

**怎么判分**（简化版，对应 `fidelity-scorecard.md:160-166` 的前三维）：

| 题 | 满意 | 不满意 → 回哪里改 |
|---|---|---|
| 已知题方向错 | — | 回第 2 步，调整模型取舍 |
| 边缘题斩钉截铁 | — | 强化“角色扮演规则”里“未表态主题标推断”那条（`skill-template.md:32`） |
| 风格题像通用 AI | — | 回第 2 步补表达DNA（句式、口癖、禁忌词） |

**一条重要的铁律**：答题和打分**不要是同一个对话**。仓库引用的研究称模型自评准确率接近随机（46.4%，`fidelity-scorecard.md:156`，论文本身我没核实）。最简单的办法：把答案拿到另一个聊天窗口，附上你查到的“真实立场”，让它打分。

**迭代上限**：最多改 2 轮，之后在诚实边界里写明薄弱处并交付（`SKILL.md:555`）。

---

## 第 6 步（可选）：写保真度评分卡

仓库有一套 100 分制评分卡（`fidelity-scorecard.md`）。如果你想把作品提交到社区索引，要求 ≥70 分，且 `FIDELITY.md` 里的日期和分数必须是**真实测出来的**，不能写“待测”“预估”（`CONTRIBUTING.md:25-26`）。没做过就**不要写**，更不要编分数。

## 第 7 步：安装并使用

**做什么**：把整个 `某人-perspective` 文件夹复制到你 AI 工具的 skills 目录（路径表见 `README.md:125-132`；Claude Code 是 `~/.claude/skills/`）。

**怎么检查对不对**：对 AI 说“用某人的视角帮我看看……”，若它进入角色，并在第一句说明“基于公开言论推断，非本人观点”，说明触发成功。再说“退出”，应当恢复正常（`skill-template.md:35`）。

## 常见问题

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| AI 说“我搜不到” | 资料太少 | 来源 <10 条时，心智模型降到 2-3 个，并在诚实边界里写明（`SKILL.md:327,651-656`） |
| AI 卡住不动 | 运行环境不支持并行子任务 | 一个维度一个维度串行做，做完就存盘（`SKILL.md:322`） |
| 对话太长，AI“忘了”前面 | 上下文窗口不足 | 按 Phase 分段，每段开头先让 AI 读已保存的文件（`SKILL.md:323`） |
| 做出来的像“名人语录集” | 把话当成了模型 | 回第 2 步，删掉没有跨域、没有排他性的条目 |
| 角色演着演着变回通用助手 | 缺防漂移规则 | 检查“角色扮演规则”是否被改动或删除（反模式 #9：`SKILL.md:621`） |
